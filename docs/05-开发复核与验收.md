# 05 · 开发复核与验收

> V1.0 最终设计基线 · 作者：ahui · 2026-10-20 · [返回总览](english-class-games-详细设计.md)

## 1. 使用方式与通过条件

制作一致性新增专项：真实Rust保存返回的递归字段重排不能触发旧成果；数组、词语、模式、声音、音乐和非法输入变化仍须识别。初存、制作、终存期间编辑与迟到取消答复分别回归，结果页只显示一处有范围的持续提示。具体行为及证据要求见 [制作成果一致性与过期保护](20-制作成果一致性与过期保护.md)，本轮实际收据存放于 `validation/production-current-20261022/`。

课堂装置标签使用实际职责名称，不能用“AI ENGINE”等装饰性字样代替智能能力证据。本轮重新复核的逐项实际结果保存在 `validation/experience-audit-20261022/`，旧报告只作为历史资料，不计为本轮通过。

开发按所属文档实现，复核检查输入、规则、输出、界面与异常是否一致，验收执行下表案例并保留证据。本文中的检查项是产品完成标准，不表示软件已经实现或已经测试。

首版只交付一个游戏及公共平台；本轮按本地规则与算法审查智能辅助，不新增大模型调用、密钥配置、学生录音或发音评分。已有可选模型接入的边界见文档 08，不作为本轮验收或离线课堂的依赖。AI 赋能必须贯穿材料复用、制作、编辑改编和成品交付，按教师取得的实际整理、推荐、编排、配音和检查成果验收，不以页面含有“AI”、规则数量或模拟进度评定。

阻止开始、保存、导出、离线上课的缺陷，内容被静默覆盖、声音与文本不符、丢词、叠音、数据损坏以及关键控件不可达均不得带入交付。功能通过但视觉、状态或边界不符合规范，同样需要修正。

表内并列场景均为必测内容；组合项按下文子编号逐条记录，其余项目按场景顺序细分记录。主项只有全部子项通过才可标记通过，部分验证、未执行和受环境限制分别说明，不以规则测试替代页面操作或实机验收。每条证据记录版本 / 文件摘要、环境、输入、操作、预期、实际结果及截图或日志；发现问题后复测该项和受影响的相邻流程。

### 2.2 固定贯穿夹具

受控词库版本为 `fixture-v1`，以下每行是一个已校对的独立教学义项；常用词库初始为空，条目默认非重点。它只用于规则验收，不替代实际分发词库。

| 英文         | 词性  | 教学义项 |
| ------------ | ----- | -------- |
| knowledge    | n.    | 知识     |
| challenge    | n.    | 挑战     |
| challenge    | v.    | 质疑     |
| take part in | phr.  | 参加     |
| and          | conj. | 和       |

另固定词形 `challenges → challenge`、功能词 `and`，`Novex` 未收录。原文固定为：

> Students face challenges and take part in a research project called Novex to build knowledge.

所有候选初始不勾选；教师仅选择 `challenges`（名词“挑战”）、`take part in`（“参加”）、`knowledge`（“知识”），分别接受释义和词性。最终为 **3 条、6 个确认补全字段**，按上述原文顺序保留，`challenges` 不改写为原形；短语内部词、功能词和未收录词不随之加入。保存这三条到常用词库，再制作和复制；替换副本时仅选 `knowledge`，应用后副本为 1 条，原件仍为 3 条。

确定计时使用配音跟读，每条英文绑定与文本匹配、可解码的 900 毫秒音频夹具；100 BPM、常规巩固，全部非重点、每条 2 轮，关闭所有口号和音乐。短语仍按短语规则留白，教师等待和暂停另计。

### 4.1 贯穿平台的完整案例

使用 [固定贯穿夹具](#22-固定贯穿夹具) 依次验收：**导入并保留原文 → 选取有来源的候选 → 确认词义并保存常用词 → 智能制作 → 手动调整并检查建议失效范围 → 复制并替换新材料 → 复用匹配声音 → 导出实际 HTML → 换机断网上课。** 配音集成部分使用实际音色与真实时长，固定音频仅用于确定计时子案例。

返回编辑、重新检查、重复导出和次日打开同一课堂文件，均保留已确认内容与编排，不重新抽选口号或调整词序；主动“换一版”才按选定范围生成新的差异。新课默认按预设词序、轮数和间隔自动运行至完成，教师可暂停、重读或切换逐词控制；不以学生发声触发推进。

记录每步的输入、真实结果、建议理由、教师确认、保留项和重新制作项；核对候选与确认数分开，来源和校对状态随接受、保存常用词、复制及导包保留，三类声音数量之和正确，原课件和手动值不被静默覆盖。确认补全覆盖已有教师值、空字段接受、重复接受、清空、撤销和无接受记录的历史数据：按当前实际补全字段计数，重复操作不累加，保存 / 复制不丢记录。建议记录须能映射到 04 §2.2 的规则编号、所用版本和实际差异；教师画面只显示通俗依据。最后检查实际文件无外部依赖。该案例必须跨页面完成，不能以单个“AI 制作”按钮的演示代替。
